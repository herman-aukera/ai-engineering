# EACHAT Final Project Live Proof Runbook

Status: manual external-evidence gate

Deterministic CI must not silently call paid providers or present fixtures as live RAG evidence. This workflow is the credentialed proof path for the exact final SHA.

## Workflow

Before the branch is merged, GitHub does not register a newly added standalone
workflow that is absent from the default branch. Use the already-registered workflow:

```text
Energy Aware Chat CI
```

Select `finalproject-GG` and run it manually. After the deterministic validation job
passes, its manual-only dependent job calls the reusable live proof with
`provider=openai` and `effort=balanced`.

After `.github/workflows/final-project-live-rag.yml` exists on the default branch,
the direct workflow is also available:

```text
Final Project - Live RAG Proof
```

Select `finalproject-GG`. Recommended direct run: `provider=openai`,
`effort=balanced`.

Required environment secret for embeddings and an OpenAI answer run:

```text
OPENAI_API_KEY
```

DeepSeek/Kimi answer selections additionally need their configured provider secret. Never paste credentials into YAML or evidence artifacts.

## Expected artifacts

The uploaded bundle contains:

```text
final-project-ingestion.json
final-project-retrieval-report.json
final-project-live-answer.json
final-project-system-eval.json
final-project-compose-smoke.json
```

`final-project-ingestion.json` should show 16 sources, at least 16 active chunks, `text-embedding-3-small`, and `vector_backend=postgresql_pgvector_hnsw`.

`final-project-retrieval-report.json` is generated by `evals/energy_chat/final_project_eval.py` and measures persisted retrieval hit@5.

`final-project-live-answer.json` is generated by `scripts/smoke_eachat_final_project_live.py`; it proves a bounded live provider call, pgvector evidence and graph-retained source refs without recording prompt/answer bodies.

`final-project-system-eval.json` is generated by `evals/energy_chat/final_project_system_eval.py`; it records disposition/clarification/escalation accuracy, retrieval/evidence presence, latency, provider calls, cost and errors over all 11 golden cases. Semantic unsupported-claim rate remains explicitly unmeasured unless a fixed judge is added.

The workflow invokes the system evaluator with `--strict`; a disposition mismatch is a
failed proof, not a green run with a low score hidden in an artifact.

`final-project-compose-smoke.json` proves that the Caddy/FastAPI/pgvector stack became
ready, returned source evidence, restarted the EACHAT container, and returned persisted
RAG evidence afterward. It records neither answers nor credentials.

## Failure handling

Keep failures visible. Source acquisition failures require source review; retrieval misses require chunk/query review; credential failures are corrected in the GitHub environment; provider failures remain live evidence and do not weaken deterministic CI boundaries.
